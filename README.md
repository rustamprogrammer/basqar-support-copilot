# Basqar — «На связи»

Поддержка Grand Mobile с тремя очередями: вопросы, жалобы, нарушения. Просьбы о помощи, платежах, доступе и пересмотре наказаний включены в жалобы. Сохранённые записи прежней ветки `request` отображаются как `complaint` при чтении; данные и решения администраторов не удаляются.

## Как устроена экономная обработка

1. Сервер загружает инструкцию v6 из `classifier-prompt.md` и ставит её в неизменное сообщение `developer`. Граница кэширования находится в конце этой инструкции.
2. `lib/glossary-hints.ts` находит до шести подходящих записей в локальном `lib/game-glossary.ts`. Исходный текст игрока и подходящие краткие русские пояснения передаются динамическим сообщением после границы кэша. Полный словарь, переводы KK/UZ и ссылки остаются локально. Это подбор контекста, не алгоритм выбора категории; исходное сообщение не переписывается.
3. Один запрос OpenAI Responses API возвращает `meaning_ru`, `box`, `needs_human`. Языки: русский, казахский, узбекский, включая смешанный текст и опечатки.
4. Одинаковые сообщения кэшируются на 10 минут (256 записей на процесс); одновременные одинаковые вызовы объединяются. Кэш результата не означает, что обращения разных игроков считаются дублями.
5. Неясное сообщение или ошибка API остаются в жалобах для ручного уточнения. Автоматических наказаний и удаления нет. Пока FAQ не подключён, вопросы рассматривает администратор.

Веб-поиск полностью удалён из API-запросов: нет `tools`, `web_search`, повторных поисков или платного перехода на другую модель. Прежняя переменная `CLASSIFIER_WEB_SEARCH` больше не используется даже при значении true. Неизвестные термины требуют ручного уточнения и последующего пополнения локального словаря.

Терминологию собираем из открытых материалов заранее. `glossary-grand-mobile.md` содержит словарь RU/KK/UZ, ссылки и ограничения. Это рабочее покрытие, а не обещание всех существующих сленговых слов. Переводы редакторские, их желательно проверить носителям языков. Полный Markdown-справочник в API не отправляется.

## API-ключ и модель

Используется ключ OpenAI API из вашего проекта. При необходимости создайте его в [API keys](https://platform.openai.com/api-keys) и сохраните локально.

В локальном `.dev.vars` заполните:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI
OPENAI_TRIAGE_MODEL=gpt-6-luna
TRIAGE_ENABLED=true
```

Ключ исключён из Git и используется только сервером. Прежние `DASHSCOPE_API_KEY`, `DASHSCOPE_BASE_URL` и `QWEN_MODEL` не используются ни приложением, ни сценариями оценки. Перезапустите сервер после изменения настроек. Для развёрнутого Worker секрет `OPENAI_API_KEY` устанавливается отдельно. Адрес API фиксирован: `https://api.openai.com/v1/responses`; пользовательский base URL не используется. Другие модели отклоняются до сетевого запроса и требуют отдельной проверки.

По умолчанию `gpt-6-luna`: `store=false`, `service_tier="default"` (Standard), `reasoning.effort="none"`, `max_output_tokens=200`, без инструментов и автоматических повторов. Есть ограничение 30 новых вызовов в минуту на процесс; это не общий денежный лимит аккаунта. Если модель недоступна, запрос отправится на ручную проверку, скрытого переключения на дорогую модель нет.

### Кэш неизменной инструкции

Рабочий режим приложения — `explicit_static`: `prompt_cache_options={mode:"explicit",ttl:"30m"}` и `prompt_cache_breakpoint` в конце статического блока `developer`. Изменяющиеся `original` и подсказки словаря идут после него. Для кэширования требуется префикс не короче 1024 видимых токенов; скрытое системное содержимое OpenAI в этот минимум не входит. [Официальное руководство по prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

Прежняя v2 была слишком короткой для кэширования: около 779 токенов текста инструкции по разнице подсчётов. В новой инструкции добавлены правила казахской и узбекской грамматики, отрицания, пересказа чужой речи, прямого оскорбления и неизвестных слов внутри понятного вопроса. В историческом тесте v4 первая запись префикса составила 1587 токенов, а в последующем прогретом тесте 96.89% входных токенов прочитаны из кэша. После изменения инструкции префикс меняется: эти длины и проценты не переносятся автоматически на v5. Это измерение на тестовом потоке, а не гарантия попадания каждого будущего запроса.

При холодном старте подходящий префикс записывается по ставке 1.25× обычного входа; чтение совпадающего префикса для Luna стоит 0.1×. Запись заменяет обычную входную плату за эти токены. `30m` задаёт минимальное время жизни, а не обещание попадания каждого запроса или ускорения. `prompt_cache_key` для оптимизации кэша этой модели не требуется; `OPENAI_API_KEY` остаётся обязательным. Автоматических платных прогревов нет. Локальный 10-минутный кэш готовых результатов работает отдельно и при попадании вообще не вызывает API. [Срок жизни и учёт кэша](https://developers.openai.com/api/docs/guides/prompt-caching).

## Стоимость и проверка качества

Тариф `gpt-6-luna` Standard на 2026-10-31 для короткого контекста: $0.10 за миллион обычных входных токенов, $0.01 за миллион входных токенов из кэша, $0.125 за миллион токенов записи кэша и $0.50 за миллион выходных. [Официальная документация GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).

Группы входных токенов учитываются раздельно: обычный вход = `input_tokens - cached_input_tokens - cache_write_input_tokens`; каждая группа оплачивается один раз по своему тарифу. Условные 1500 обычных входных + 100 выходных = $0.00020 за обращение, $2.00 за 10 000. Если все 1500 входных относятся к записи кэша, тот же пример = $0.0002375. Это расчёт, не замер и не выписка биллинга. При попадании в локальный кэш API не вызывается. Фактический `usage` сохраняется в `processing.ai`; при сетевом сбое расходы могут быть неизвестны.

Время ожидания API ограничено 4.5 секундами. На последней выборке p95 серверного классификатора v4 — 3.835 секунды; средняя цена с учётом неизвестного списания при таймауте — $0.00004197–$0.00006478. Первый холодный вызов v4 стоил $0.000227475 с записью префикса. Общую задержку сайта и расходы на реальном потоке нужно измерять отдельно; качество по-прежнему требует ручной разметки RU/KK/UZ.

Тесты без расходов: `node --test lib/classifier.test.ts lib/glossary-hints.test.ts lib/message-types.test.ts`. С настоящим ключом: `node --env-file=.dev.vars scripts/classifier-smoke.mjs --live` (до четырёх запросов, без поиска). Примеры из инструкции проверяют интеграцию, а не независимую точность. Для оценки используйте отдельную ручную разметку; считайте ошибки по трём веткам, по языкам и долю передач человеку. Нельзя обещать 100% точность.

Данные организаторов и производные выборки не публикуйте; `data/`, `private-data/` и `eval-results/` исключены из Git.

Последующие ответы администраторов использованы во втором слепом модельном разборе: совпадение составило **1249/1299 = 96.15%**, но это согласие двух моделей, а не подтверждённая человеком точность. Отдельная разметка по админответам стоила $0.5988285 и не входит в рабочую цену одного обращения.

В историческом [отчёте итераций v3/v4](eval-prompt-v3-2026-10-31.md) сохранены оба этапа, включая регрессию v3 и её точечную правку. В сравнении на 54 новых для того этапа сообщениях согласие с предварительными модельными метками — 50/54 у v2 и 49/54 у v4. На 51 паре с пригодными ответами категории полностью совпали; различия общего результата вызваны сбоями обработки. Стоимость этих одинаковых 51 обращений снизилась на 61.43% при прогретом кэше. Рост языкового качества не показан. На 12 отдельных новых контрольных KK/UZ-примерах оба варианта дали 12/12; это синтетические примеры, не ручной эталон. Реальная выборка включает по 18 RU/UZ из validation и KK из train, поскольку свежие KK validation исчерпаны.

Историческое сравнение v1→v2: [разбор расхождений и парное сравнение](eval-prompt-v2-2026-10-31.md). На одинаковых 90 новых для того прогона сообщениях согласие с предварительными метками выросло с 82/90 до 87/90. Это не подтверждённая человеком точность. У версии v2 остались один вопрос в жалобах и два таймаута; по языкам RU 24→30/30, KK 28→28/30, UZ 30→29/30. В отдельных 18 синтетических примерах оба варианта дали 18/18.

Критерий хакатона — **$0.002 за одно обращение**, а не за всю выборку. Средняя цена версии v2 в том A/B находилась между $0.00010874 известных расходов на сообщение и $0.00012605 с консервативным резервом неизвестных попыток. Старая версия v1 была фактически дешевле благодаря кэшу OpenAI; v2 была короче, но в этом прогоне не получила скидки чтения кэша. Точный итог неизвестен из-за трёх таймаутов в двух вариантах. Сравнивается стоимость классификации, разметка/аудит оплачиваются отдельно только при оценке.

Исторический первый запуск: [отчёт оценки v1](eval-report-2026-10-31.md). Его проценты на другой выборке нельзя напрямую сравнивать с новым прогоном.

`tickets_valid.jsonl` содержит 1000 обращений, но не содержит правильных меток наших трёх веток. `kind` — источник сообщения, а `violation` — результат рассмотрения жалобы, не нарушение её автора. В модель передаётся только текст игрока, без ответа администратора и результата рассмотрения.

`scripts/prepare-classifier-eval.ps1` создаёт фиксированную случайную выборку из 100 допустимых сообщений и метаданные. Параметры: `-Archive <handout.tgz> -OutputDirectory <локальная-папка>`. Исходные тексты в консоль не выводятся. В Windows с блокировкой записи в Documents используйте каталог внутри `$env:TEMP`. Оригиналы и результаты оценки должны оставаться вне публичного репозитория.

Для отдельного сравнения языков добавьте `-PerLanguage 30`: получится 90 сообщений, по 30 RU/KK/UZ согласно исходным эвристическим языковым меткам. Это диагностическая выборка с равными долями языков; её среднее нельзя считать средним по всему потоку. Храните её отдельно от случайной выборки и проверьте язык и правильную категорию при ручной разметке.

Обновлённый sampler использует Python со стандартной библиотекой, исключает повторы нормализованного текста и поддерживает `-ExcludeSamples @('<прошлая-выборка-1.jsonl>', '<прошлая-выборка-2.jsonl>')`. `-AvailabilityOnly` показывает доступные количества без сохранения данных. Если новых KK в validation не осталось, явный `-IncludeTrainKazakh` добирает их из train и сохраняет `origin`; такой срез нужно показывать отдельно. Нельзя смешивать его с результатами validation без указания происхождения.

Для честного A/B сохраните обе инструкции до запуска и используйте одни метки для обоих вариантов:

```powershell
node --env-file=.dev.vars scripts/eval-paired-classifier.mjs --live --input "<новая-выборка.jsonl>" --old-prompt "<старая-инструкция.md>" --new-prompt "classifier-prompt.md" --old-cache-mode legacy_implicit --new-cache-mode explicit_static --labels "<предварительные-метки.jsonl>" --output "<новая-папка-A-B>"
```

Эта команда сравнивает одновременно инструкцию и конфигурацию кэша. Для сравнения только инструкций задайте одинаковые режимы. Без параметров `--old-cache-mode` и `--new-cache-mode` парный сценарий использует `legacy_implicit` для обоих вариантов, сохраняя воспроизводимость прежних прогонов; приложение и одиночный `eval-classifier.mjs` по умолчанию используют `explicit_static`. Выбранные режимы записываются в метаданные оценки.

Общий лимит обоих вариантов — $0.15. Одиночный таймаут сохраняет неизвестную стоимость и резерв, повторов нет; отказы доступа/квоты и три последовательных сбоя останавливают прогон. В выходных файлах нет исходного текста. Для разбора прошлых расхождений есть `scripts/audit-classifier-errors.mjs --help`: его диагностические выводы нельзя принимать за независимые эталонные метки. Проверки без API: `node --test lib/classifier.test.ts lib/glossary-hints.test.ts lib/message-types.test.ts scripts/eval-metrics.test.mjs scripts/eval-paired-classifier.test.mjs`.

Проверка конфигурации без генерации:

```powershell
node --env-file=.dev.vars scripts/eval-classifier.mjs --input "<путь-к-выборке.jsonl>"
```

Измерение с расходованием API-баланса:

```powershell
node --env-file=.dev.vars scripts/eval-classifier.mjs --live --input "<путь-к-выборке.jsonl>" --output "<новая-локальная-папка-результатов>"
```

Сценарий использует тот же классификатор, максимум 100 сообщений, без веб-поиска и повторов; проверяет консервативную оценку следующего запроса перед превышением бюджета $0.10 и останавливается при отказе доступа/квоты, неизвестной стоимости или трёх последовательных ошибках. Это не лимит расходов аккаунта. API-ответы без `usage` учитываются как неизвестная стоимость. Чтение и запись кэша OpenAI тарифицируются отдельно от обычного входа; локальный кэш не вызывает API. В отчёте сохраняются расходы, покрытие, задержки и агрегаты. Повторный запуск должен использовать новую папку, чтобы не стереть предыдущий результат.

Поле `expected_box` заполняется независимо до сравнения. Без него accuracy остаётся `null`. Ошибка API считается непроклассифицированным обращением, даже если резервная очередь — жалобы. Разметка другой моделью даёт только предварительное согласие моделей; её нельзя называть проверенной человеком точностью. Среднее по этой выборке относится к составу validation, а не гарантирует расходы и качество на всём игровом трафике.

Опционально `scripts/annotate-eval.mjs --live --input <sample.jsonl> --output <новая-папка>` получает слепую предварительную разметку через `gpt-6-sol` (до пяти дополнительных платных запросов, отдельный бюджет $0.20). Запускайте с `node --env-file=.dev.vars`; модели не передаются результаты классификатора или ответы администраторов. Сравнение: `node scripts/compare-classifier-eval.mjs --results <classifier-results.jsonl> --labels <judge-labels.jsonl> --output <agreement.json>`. Отчёт явно обозначает согласие моделей, показывает базовую долю большинства, матрицу ошибок и срезы по языкам. Две модели одного семейства могут допускать одинаковые ошибки, поэтому нужна ручная проверка. Расходы разметки учитываются отдельно от стоимости обработки обращения. Для исторических результатов OpenAI без поля `model` укажите в сравнении `--model gpt-6-luna`; это только перерасчёт сохранённых данных, без API-вызовов.

## Первый запуск

Команды выполняйте в терминале. В Windows подойдёт PowerShell или командная строка.

### 1. Скачать проект и собрать

```sh
git clone https://github.com/BAITC-Hacks/hack-b6eba4f7-basqar.git
cd hack-b6eba4f7-basqar
npm run install:ci
npm run build
```

### 2. Создать локальную базу данных

Выполните три команды по порядку **один раз для новой базы**:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_bumpy_raider.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_sloppy_joshua_kane.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_greedy_charles_xavier.sql
```

Отдельный сервер базы данных и аккаунт Cloudflare для локального запуска не требуются. Сообщения хранятся в `.wrangler/state/` и сохраняются после перезапуска. Не удаляйте эту папку, если хотите сохранить обращения. В Git она не загружается.

Если база уже создана, выполняйте только ещё не применённые миграции. Первая создаёт таблицу, вторая добавляет `original_text`, третья — `processing` для истории этапов. При обновлении версии с исправлением текста, но без истории этапов, нужна только третья команда.

### 3. Запустить сайт

```sh
npm start -- --port 8787
```

Откройте [http://127.0.0.1:8787](http://127.0.0.1:8787). Для остановки нажмите **Ctrl+C** в терминале. При следующих запусках достаточно этой команды.

## Доступ по ссылке, пока работает ноутбук

В Windows после сборки и создания базы:

1. Установите `cloudflared` и убедитесь, что команда `cloudflared --version` работает в новом терминале.
2. Если сайт запущен командой `npm start`, остановите его через **Ctrl+C**, чтобы освободить порт 8787.
3. Откройте `start-site.cmd` двойным щелчком или выполните `./start-site.cmd` в PowerShell.
4. Скопируйте показанную ссылку вида `https://….trycloudflare.com` и отправьте её другим людям.

Скрипт запускает сайт и туннель в фоне; окно запуска можно закрыть. Ноутбук должен оставаться включённым, подключённым к интернету и не переходить в спящий режим. После остановки и нового запуска туннеля ссылка меняется.

Для остановки откройте `stop-site.cmd`. Повторный запуск `start-site.cmd` при уже работающем сайте покажет текущую ссылку.

В macOS/Linux запустите сайт через `npm start -- --port 8787`, а в другом терминале выполните:

```sh
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8787 --protocol http2
```

Оставьте оба терминала работающими; для остановки используйте **Ctrl+C** в каждом.

## Как пользоваться

1. Выберите **«Пользователь»**, введите сообщение и нажмите кнопку отправки.
2. Если текст изменился, сайт покажет исправленный вариант и исходный текст.
3. Выберите **«Админ»**, чтобы увидеть очередь, принятые сообщения и корзину. Список обновляется автоматически.
4. Нажмите **«Этапы обработки»** под отправленным сообщением или откройте **«Логика»**, чтобы просмотреть его этапы. После решения администратора результат обновится автоматически.

Это демонстрационный проект: переключатель ролей не защищён паролем. Любой посетитель сайта может открыть панель администратора, читать обращения и менять их статус.

## Разработка и обновление

После установки зависимостей и создания базы режим разработки запускается командой:

```sh
npm run dev -- --hostname 127.0.0.1
```

Адрес разработки: [http://127.0.0.1:5173](http://127.0.0.1:5173). Изменения исходников подхватываются автоматически.

Чтобы обновить собранную версию, сначала остановите её через `stop-site.cmd` или **Ctrl+C**, затем выполните:

```sh
git pull
npm run install:ci
npm run build
```

После этого снова используйте `start-site.cmd` для доступа по ссылке или `npm start -- --port 8787` для локального запуска. Существующая база останется на месте; новые миграции, если они появятся, нужно применять отдельно.

Проверка обработки сообщений и типов:

```sh
node --test lib/classifier.test.ts
npx tsc --noEmit
```

## Структура

- `app/page.tsx` — интерфейсы пользователя и администратора.
- `app/logic/page.tsx` — история этапов конкретных обращений.
- `app/api/messages/route.ts` — получение, отправка и изменение статуса сообщений.
- `classifier-prompt.md` — инструкция v6 для трёх веток и грамматики RU/KK/UZ/UK, без веб-поиска.
- `glossary-grand-mobile.md` и `lib/game-glossary.ts` — локальная терминология RU/KK/UZ и источники.
- `lib/glossary-hints.ts` — выбор только подходящих пояснений для запроса к модели.
- `lib/classifier.ts` — серверный вызов OpenAI Responses API, проверка JSON, кэш и обработка ошибок.
- `lib/classifier-message.ts` — сохранение выбранной категории и этапов обработки.
- `db/` и `drizzle/` — схема базы и SQL-миграции.
- `scripts/local-public.ps1` — запуск и остановка публичной ссылки в Windows.

Стек: React, TypeScript, Vinext/Vite, Drizzle ORM, локальная Cloudflare D1 (SQLite), Wrangler; Cloudflare Tunnel для доступа по ссылке.
