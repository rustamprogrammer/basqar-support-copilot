# Basqar — «На связи»

Сайт для обращений игроков Grand Mobile. Категории: **Вопрос**, **Помощь**, **Нарушение**, **Корзина**, **Неопределённо**. Поддерживаются русский, казахский, узбекский и украинский текст, известные опечатки, транслит и игровой жаргон.

Обработка новых сообщений: **локальный алгоритм → проверка ИИ → итог**. ИИ получает исходник и результат алгоритма, подтверждает его или возвращает исправленный вариант. История видна в разделе «Логика». Без подключения ИИ сайт работает на локальных правилах. Автоответы игрокам и автоматическое наказание не включены.

## Что установить

- [Node.js 24.x](https://nodejs.org/en/download) с npm. Проверено на Node.js 24.19.0.
- [Git](https://git-scm.com/downloads/).
- Для публичной ссылки — [cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/). После установки откройте новый терминал и проверьте `cloudflared --version`.

## Первый запуск (Windows)

Откройте PowerShell. Все команды ниже выполняйте из папки проекта.

### 1. Скачать проект и собрать

```powershell
git clone https://github.com/BAITC-Hacks/hack-b6eba4f7-basqar.git
cd hack-b6eba4f7-basqar
npm run install:ci
npm run build
```

### 2. Создать базу

Выполните пять команд по порядку **один раз для новой базы**:

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_bumpy_raider.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_sloppy_joshua_kane.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_greedy_charles_xavier.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_feedback.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0004_feedback_routing.sql
```

Отдельный сервер базы и аккаунт Cloudflare для локального запуска не нужны. Сообщения хранятся в `.wrangler/state/` и сохраняются после перезапуска. Эта папка не загружается в GitHub: на другом компьютере после установки будет пустая база.

Для существующей базы применяйте только недостающие миграции. Если есть поле `processing`, но нет таблицы `message_feedback`, нужны `0003` и `0004`. Если `message_feedback` уже создана прежней версией, но нет поля `routing_schema`, нужна `0004`. Повторно выполнять уже применённые команды нельзя. Перед обновлением сохраните резервную копию базы при остановленном сервере.

### 3. Запустить

Для запуска **с нашим подключением ИИ** выполните следующий раздел. Для запуска только с алгоритмом:

```powershell
npm start -- --port 8787
```

Сайт: [http://127.0.0.1:8787](http://127.0.0.1:8787). Остановка — **Ctrl+C**. При следующих запусках установка и создание базы не требуются.

## Подключение ИИ

Используется OpenAI Responses API; модель в текущем коде — `gpt-6-luna`. Нужен свой действующий API-ключ с доступом к модели и средствами на API. Ключ вводится на сервере, а исходное сообщение и результат алгоритма отправляются в API для проверки.

Остановите ранее запущенный сайт через `stop-site.cmd` или **Ctrl+C**. Затем в PowerShell из папки проекта выполните:

```powershell
$reviewKey = Read-Host "OpenAI API key" -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new("", $reviewKey).Password
Remove-Variable reviewKey
$env:AI_REVIEW_ENABLED = "true"
$env:CLOUDFLARE_INCLUDE_PROCESS_ENV = "true"
npm start -- --port 8787
```

Вставьте ключ в скрытое поле запроса и нажмите Enter. Он не попадёт в текст команды или файлы проекта. Переменные действуют в текущем PowerShell и запущенных из него процессах. После закрытия терминала при новом запуске ввод повторяется. Не добавляйте ключ в Git, клиентский код или конфигурацию сборки.

**Для публичной ссылки вместо последней команды выполните `./start-site.cmd` в том же окне PowerShell.** Двойной щелчок по файлу не получает переменные из этого окна. Также уже работающий сервер не получит новый ключ без перезапуска.

Проверка подключения:

1. Откройте [http://127.0.0.1:8787/api/health](http://127.0.0.1:8787/api/health): `ok: true` означает доступность сайта и базы, `aiReviewEnabled: true` — наличие ключа и включающего флага.
2. Отправьте одно новое сообщение и откройте его «Этапы обработки». Успешный вызов подтверждается результатом проверки ИИ в «Логике». Сам флаг `aiReviewEnabled` не проверяет действительность ключа или доступ к API.

Если ИИ отключён, недоступен или достигнут лимит, обращение сохраняется с результатом алгоритма и отметкой об отсутствии проверки. Исторические сообщения автоматически не пересчитываются. Для отключения задайте `$env:AI_REVIEW_ENABLED = "false"` и перезапустите сервер.

Лимиты на один процесс: 200 вызовов до перезапуска, 20 за минуту, 4 одновременно. Успешные одинаковые проверки кешируются на 10 минут, до 128 результатов. Лимиты сбрасываются при перезапуске; это не общий денежный бюджет. Отправки через публичную ссылку могут расходовать средства API.

## Публичная ссылка с ноутбука

После сборки, создания базы и установки `cloudflared`:

1. Если сайт запущен через `npm start`, остановите его через **Ctrl+C**.
2. Запустите `./start-site.cmd` из PowerShell с переменными ИИ, как описано выше. Для режима без ИИ можно открыть файл двойным щелчком.
3. Сайт откроется в браузере. Ссылка для других людей появится в окне запуска и в `site-link.txt`. Повторно открыть её можно через `open-site.url`.

Сервер и туннель работают в фоне: окно запуска можно закрыть. Ноутбук должен оставаться включённым, подключённым к интернету и без спящего режима. После перезапуска туннеля адрес меняется; повторное открытие `start-site.cmd` при работающем сайте показывает прежний адрес.

Остановка — `stop-site.cmd`. База сохраняется. Если туннель не запустился, локальный сайт продолжает работать на [http://127.0.0.1:8787](http://127.0.0.1:8787); причина отсутствия публичной ссылки появится в окне запуска.

В macOS/Linux сайт запускается через `npm start -- --port 8787`, а туннель — в отдельном терминале:

```sh
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8787 --protocol http2
```

Для ИИ задайте те же три переменные окружения в терминале серверного процесса средствами своей оболочки. Оба процесса должны оставаться запущенными.

## Как пользоваться

1. В режиме **«Пользователь»** введите обращение и отправьте его.
2. В режиме **«Админ»** откройте категорию, просмотрите исходник, исправленный текст, решение и уточняющий вопрос; при необходимости измените статус.
3. В **«Логике»** видны этапы выбранного сообщения, результат алгоритма и проверка ИИ.
4. В **«Качестве»** доступны исторические прогоны правил, PDF и архив синтетического набора. Эти показатели не являются точностью текущего ИИ на реальных обращениях.

Роли в демо открыты без пароля: любой посетитель может читать обращения и менять их статус. Исправления администратора сохраняются как предложения; автоматическое обучение по ним не запускается.

## Обновление и проверки

Остановите сервер через `stop-site.cmd` или **Ctrl+C**, сохраните резервную копию `.wrangler/state/`, затем выполните:

```powershell
git pull --ff-only
npm run install:ci
npm run build
```

Примените новые миграции, если они появились, и повторите запуск с нужными переменными ИИ. Существующую базу удалять не нужно.

Проверки без платных API-вызовов:

```powershell
npm test
npx tsc --noEmit
```

Режим разработки: `npm run dev -- --hostname 127.0.0.1`, адрес [http://127.0.0.1:5173](http://127.0.0.1:5173). Для обновления обычного запуска после изменений снова нужны сборка и перезапуск.

| Проблема | Что проверить |
| --- | --- |
| `npm` или `node` не найдены | Установите Node.js и откройте новый терминал. |
| Нет `dist/server/wrangler.json` | Выполните `npm run build`. |
| `no such table` / `no such column` | Примените недостающие миграции к локальной базе. |
| Нет публичной ссылки | Проверьте `cloudflared --version`, интернет и сообщение в окне запуска. |
| ИИ выключен после двойного щелчка | Остановите сервер и запустите скрипт из PowerShell, где введены переменные ИИ. |
| `aiReviewEnabled: true`, но ИИ недоступен | Проверьте ключ, средства API, доступ к модели и интернет. «Логика» показывает, состоялась ли проверка; технический код ошибки сохраняется в `processing.aiReview.errorCode` записи `/api/messages`. |

## Основные файлы

- `app/page.tsx`, `app/logic/`, `app/quality/` — сайт, история обработки и качество.
- `app/api/messages/route.ts` — отправка и изменение обращений.
- `lib/message-processing.ts` — локальный алгоритм; словари и контекст находятся рядом в `lib/`.
- `lib/hybrid-processing.ts` — проверка ИИ, лимиты и кеш.
- `lib/server-review.ts`, `lib/ai-review-client.ts`, `lib/ai-review-prompt.ts` — серверное подключение и инструкции модели.
- `db/`, `drizzle/` — схема и миграции базы.
- `scripts/local-public.ps1`, `start-site.cmd`, `stop-site.cmd` — запуск и остановка публичной ссылки.
- [docs/processing.md](docs/processing.md) — подробности обработки и команды оценки правил.

Стек: React, TypeScript, Vinext/Vite, Drizzle ORM, локальная Cloudflare D1 (SQLite), Wrangler и Cloudflare Tunnel. Ключи, локальная база, служебные логи и реальные выгрузки обращений исключены из Git.
