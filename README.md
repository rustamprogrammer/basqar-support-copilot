# Basqar — «На связи»

Стенд разработки, разметки и демонстрации обработки обращений Grand Mobile: **Вопрос**, **Помощь**, **Нарушение**, **Корзина**, **Неопределённо**. Алгоритмы обрабатывают известные опечатки, транслит, игровой жаргон и обращения на русском, казахском, узбекском и украинском. Непонятые сообщения требуют администратора.

По умолчанию сервер работает **по алгоритмам, без платных запросов**. В «Настройках» можно подключить свой OpenAI API-ключ: ИИ будет проверять решение алгоритма, уточнять срочность и выбирать готовый ответ из опубликованной базы. До подключения ключа все основные функции доступны бесплатно.

## Что установить

- [Node.js 24.x](https://nodejs.org/en/download) с npm. Проверено на Node.js 24.19.0.
- [Git](https://git-scm.com/downloads/).
- Для публичной ссылки — [cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/). После установки откройте новый терминал и проверьте `cloudflared --version`.

## Как проверять стенд

1. **Проверка сообщения**: введите текст или выберите пример из списка. Результат появляется в отдельной карточке: категория, исправление, ответ и этапы обработки. Сообщение сохраняется в базе.
2. **Тесты и статистика → Проверить тексты**: вставьте до 1000 строк. Пакет идёт по 10 сообщений, его можно остановить и продолжить. Эта проверка не добавляет обращения, не вызывает ИИ и использует начальную базу ответов; изменения карточек проверяются отправкой на главной.
3. Укажите ожидаемые категории вручную, включите фильтр несовпадений и скачайте JSON. Без ваших меток система показывает распределение результатов, а не выдаёт свои предсказания за измеренную точность.
4. **Обращения**: откройте без пароля, найдите обращение, проверьте срочность и ответьте. Исправление оценки находится в «Анализ и разметка», перемещение — в «Изменить категорию». Поиск и фильтры работают по всей базе; на экран загружается 20 записей. Очистка всей базы находится в «Управление тестовыми данными» и требует подтверждения.
5. **Логика** загружает только выбранное обращение и краткий список последних 100. Поиск позволяет найти старые записи. Сохранённые проверки в статистике отделены от новых запусков и исторических версий ИИ.

Исправление разметки и добавление карточек сами по себе не обучают веса модели и не меняют правила маршрутизации. Версия политики и состояние подключения видны в настройках.

## Первый запуск (Windows)

Откройте PowerShell. Команды выполняются из папки проекта.

### 1. Скачать и собрать

```powershell
git clone https://github.com/BAITC-Hacks/hack-b6eba4f7-basqar.git
cd hack-b6eba4f7-basqar
npm run install:ci
npm run build
```

### 2. Создать базу

Для **новой** базы выполните семь миграций по порядку, один раз:

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_bumpy_raider.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_sloppy_joshua_kane.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_greedy_charles_xavier.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_feedback.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0004_feedback_routing.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0005_assistance.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0006_ai_settings.sql
```

Отдельный сервер базы и аккаунт Cloudflare для локального запуска не нужны. Данные хранятся в `.wrangler/state/` и сохраняются после перезапуска. На другом компьютере после установки будет пустая база.

Для существующей базы применяйте **только недостающие миграции**. После `0000`–`0004` нужны `0005_assistance.sql` (база знаний и очередь помощи) и `0006_ai_settings.sql` (настройки ИИ и счётчик запросов). Если `0005` уже применена, выполните только `0006`. Перед обновлением сохраните копию базы при остановленном сервере.

### 3. Запустить

```powershell
npm start -- --port 8787
```

Откройте [http://127.0.0.1:8787](http://127.0.0.1:8787). Остановка — **Ctrl+C**. При следующих запусках установка и создание базы не требуются.

Проверка [http://127.0.0.1:8787/api/health](http://127.0.0.1:8787/api/health) должна показать `ok: true`, `processingMode: "rules"`, `aiReviewEnabled: false`, `adminConfigured: true`, `publicDemo: true`.

## Вход администратора

По умолчанию это **публичный демонстрационный стенд без пароля**. Откройте **«Обращения»**: очередь, ответы, разметка и база знаний доступны сразу. Любой посетитель публичной ссылки имеет те же возможности. `npm start` и `start-site.cmd` включают этот режим; старый файл пароля не используется. Управление API-ключом и ручная платная проверка доступны только через локальный адрес на ноутбуке.

При необходимости закрытый режим можно явно включить перед запуском:

```powershell
$env:SUPPORT_DEMO_MODE='false'
npm start -- --port 8787
```

Только в закрытом режиме пароль хранится в `.sites-runtime/admin-password.txt`, а посетители видят обращения своего браузера. Для возврата открытого стенда уберите переменную или задайте `SUPPORT_DEMO_MODE=true` и перезапустите сервер.

## Публичная ссылка с ноутбука

После сборки, создания базы и установки `cloudflared`:

1. Если сайт запущен через `npm start`, остановите его через **Ctrl+C**.
2. Откройте `start-site.cmd` двойным щелчком или выполните `./start-site.cmd` из PowerShell.
3. Сайт откроется в браузере. Публичная ссылка появится в окне запуска и в `site-link.txt`. Повторно открыть её можно через `open-site.url`.

Сервер и туннель работают в фоне: окно запуска можно закрыть. Ноутбук должен оставаться включённым, подключённым к интернету и без спящего режима. После перезапуска туннеля адрес меняется; повторное открытие `start-site.cmd` при работающем сайте показывает прежний адрес.

Остановка — `stop-site.cmd`. База сохраняется. Если туннель не запустился, локальный сайт продолжает работать на [http://127.0.0.1:8787](http://127.0.0.1:8787); причина отсутствия ссылки появится в окне запуска.

В macOS/Linux сайт запускается через `npm start -- --port 8787`, а туннель — в отдельном терминале:

```sh
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8787 --protocol http2
```

Оба процесса должны оставаться запущенными.

## Срочность и готовые ответы

В **«Помощи»** алгоритм оценивает происходящее, время события, отрицания и продолжение последствий:

| Уровень | Когда используется |
| --- | --- |
| **Сейчас** (`now`) | Нападение или другое событие продолжается; администратору нужно успеть помочь либо увидеть происходящее. |
| **Высокий** (`high`) | Сохраняется блокировка игры, доступа или существенная потеря: застревание, недоступный аккаунт, отсутствующая покупка. |
| **Обычный** (`normal`) | Завершённая ситуация без продолжающегося ущерба; либо пока недостаточно данных и нужно уточнение. |

Само слово «срочно» не повышает уровень. Приоритет означает необходимость проверки, а не доказанность нарушения. Срочное обращение не ждёт заполнения ID и других деталей. Дополнение игрока может изменить срочность; истечение времени само по себе не решает проблему.

В **«Вопросах»** доступно 24 начальные карточки определений игровых терминов. Готовые тексты сейчас на русском. Алгоритм сопоставляет весь вопрос, проверяет исключения и выдаёт опубликованный ответ только при уверенном совпадении. Вопросы о конкретном наказании, разрешённых действиях, личном происшествии, неизвестной инструкции или сразу нескольких темах передаются администратору. Упоминание «ДМ» не заменяет помощь справкой.

У ответа есть действия **«Помогло»** и **«Нужен администратор»**. При передаче человеку сохраняются исходное обращение, уже выданный ответ и дополнение. Отправка справки не считается автоматическим решением проблемы.

Администратор управляет карточками базы: текстом, условиями совпадения, исключениями, источником, версией и статусом публикации. Новые ответы сначала проверяются как черновики. Исправления и обратная связь не запускают автоматическое обучение.

В **«Логике»** показаны маршрут, причина срочности и решение о готовом ответе. В **«Качестве»** сохраняются исторические показатели; они не являются оценкой текущей версии на живых обращениях.

Словарь поиска учитывает формы игровых действий: «ДМить», «дмят», «ДБшить», «МГшить», «флудить» и другие. Поддерживаются конструкции «ДМить — это что?», «Как понимать слово…», известные опечатки, слитные слова и смешанная запись вроде `DMить`. Это нормализация вопроса для поиска; исходный текст и утверждённый ответ сохраняются. «Меня ДМят» и «Можно ли ДМить?» не получают справку вместо разбора ситуации или правил. Неизвестные формулировки остаются администратору.

## Подключение своего ИИ

1. Запустите сайт и откройте [локальные настройки](http://127.0.0.1:8787/settings) на ноутбуке.
2. Вставьте свой **OpenAI API-ключ**, укажите доступную вашему аккаунту модель и нажмите «Сохранить настройки». Повторное сохранение с новым ключом заменяет старый; пустое поле оставляет сохранённый ключ.
3. При необходимости нажмите «Проверить · 1 платный запрос». Проверка учитывается в общем лимите и не повторяется автоматически.
4. Включите ИИ для новых сообщений и нажмите «Сохранить настройки». Режим «Только сложные и неясные обращения» экономит запросы; режим «Все новые обращения» проверяет остальные решения, кроме явных нарушений.

Сначала работают алгоритмы. ИИ получает исходный текст, компактный результат и до восьми подходящих опубликованных карточек. Он может подтвердить или заменить решение, повысить срочность помощи и выбрать утверждённый ответ. Неизвестные правила, спорные наказания, обращения без достаточных деталей и личные проблемы передаются администратору. Свободный придуманный ответ ИИ игроку не отправляется. При сбое API сохраняется результат алгоритма.

**Максимум 100 запросов на установку.** Счётчик сохраняется в базе, учитывает ручную проверку и не сбрасывается заменой ключа, включением ИИ или перезапуском. После лимита сервер продолжает работать по алгоритмам. Ошибки и тайм-ауты тоже занимают попытку: это предохраняет от повторных расходов. Массовые тесты на странице статистики и `npm test` не обращаются к API. Лимит запросов не является долларовым лимитом: стоимость зависит от модели и токенов.

Ключ зашифрован в локальной базе. На экране видны только последние четыре символа. Секрет шифрования создаётся в `.sites-runtime/settings-secret` и исключён из Git вместе с базой; храните его вместе с резервной копией `.wrangler/state/`. Не переносите ключи в исходники, README или конфигурацию сборки. Кнопка «Удалить ключ» отключает ИИ. Публичный адрес позволяет просматривать состояние подключения, но не менять ключ и не запускать ручную платную проверку.

Наш навык описан в [skills/grand-mobile-support/SKILL.md](skills/grand-mobile-support/SKILL.md). Каноническая политика находится в `lib/ai-review-prompt.ts` и действительно передаётся модели. Она учитывает RU/UK/KK/UZ, слитные слова, раскладку, пересказ чужих оскорблений, текущие и прошлые события. [Справочник и официальные источники](skills/grand-mobile-support/references/domain.md) отделяют правила игры от нашей политики срочности. Это инструкции и контекст, а не обучение весов или гарантия знания всех серверных исключений.

Используется OpenAI Responses API с ограниченной JSON-схемой и `store: false`; свободный текст ответа и ошибки провайдера не попадают в интерфейс. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses).

## Обновление и проверки

Остановите сайт, сохраните резервную копию `.wrangler/state/`, затем выполните:

```powershell
git pull --ff-only
npm run install:ci
npm run build
```

Примените новые миграции и повторите `npm start -- --port 8787` либо `start-site.cmd`. Существующую базу и файл пароля удалять не нужно. Запущенный сервер использует прежнюю сборку до перезапуска.

Проверки без API:

```powershell
npm test
npx tsc --noEmit
node scripts/assistance-evaluate.mjs --mode current --split development --stage development-check
```

В [evaluation/README.md](evaluation/README.md) описана независимая разметка 1000 проверок срочности и 1000 FAQ, разбиение по смысловым семействам и порядок итогового holdout-прогона. Это синтетические тесты, не обещание точности на реальных обращениях.

Режим разработки: `npm run dev -- --hostname 127.0.0.1`, адрес [http://127.0.0.1:5173](http://127.0.0.1:5173). Для проверки демонстрационного режима используйте сборку и `npm start`: именно этот запуск задаёт `SUPPORT_DEMO_MODE` серверу.

| Проблема | Что проверить |
| --- | --- |
| `npm` или `node` не найдены | Установите Node.js и откройте новый терминал. |
| Нет `dist/server/wrangler.json` | Выполните `npm run build`. |
| `no such table` / `no such column` | Примените недостающие миграции, включая `0005_assistance.sql` и `0006_ai_settings.sql`. |
| Нет публичной ссылки | Проверьте `cloudflared --version`, интернет и сообщение запуска. |
| Неожиданно требуется пароль | Запускайте через `npm start` или `start-site.cmd`; проверьте, что `SUPPORT_DEMO_MODE` не задан как `false`, и перезапустите сервер. |
| На сайте видна прежняя версия | Выполните сборку и перезапустите сайт; повторный запуск скрипта при работающем сервере лишь показывает ссылку. |

## Основные файлы

- `app/page.tsx`, `app/logic/`, `app/quality/` — сайт, история обработки и качество.
- `app/api/messages/`, `app/api/admin/` — обращения и вход администратора.
- `lib/support-processing.ts`, `lib/help-urgency.ts` — обработка без ИИ и срочность.
- `lib/knowledge-base.ts`, `lib/knowledge-matching.ts` — начальная база и подбор ответа.
- `lib/message-processing.ts` и соседние модули — нормализация, языки и маршрутизация.
- `lib/server-review.ts`, `lib/ai-settings.ts`, `lib/ai-settings-review.ts` — настройки, лимит и проверка решений через ИИ.
- `lib/ai-review-client.ts`, `lib/ai-review-prompt.ts` — клиент API и актуальные инструкции модели.
- `db/`, `drizzle/` — схема и миграции базы.
- `scripts/start-local.mjs` — запуск деморежима без пароля и загрузка секрета шифрования; ИИ включается в настройках.
- `scripts/local-public.ps1`, `start-site.cmd`, `stop-site.cmd` — публичная ссылка и остановка.
- [docs/processing.md](docs/processing.md) — дополнительные и исторические сведения об обработке.

Стек: React, TypeScript, Vinext/Vite, Drizzle ORM, локальная Cloudflare D1 (SQLite), Wrangler и Cloudflare Tunnel. Пароль, ключи, локальная база, служебные логи и реальные выгрузки обращений исключены из Git.
