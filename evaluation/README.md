# Проверка срочности и готовых ответов

`support-assistance-cases.json` содержит 1000 строк для срочности и 1000 для готовых ответов. Это **синтетические проверки**, не обращения игроков и не копии закрытого конкурсного набора.

Ожидаемые решения заданы вручную до просмотра новых реализаций срочности и FAQ. Одна смысловая семья содержит четыре языковые версии (русский, украинский, казахский, узбекский) и пять вариантов написания: обычный, верхний регистр, пунктуация/эмодзи, пропуск буквы, слитные слова или транслит. Всего 100 смысловых семей. Таким образом, 2000 строк нельзя считать 2000 независимых реальных случаев. Языковые варианты не прошли отдельную проверку носителями.

Во всём файле 1913 уникальных текстов: часть отрицательных примеров повторяется между механизмами, а строки из цифр или эмодзи не меняются при смене регистра. Язык таких строк обозначает набор варианта, а не установленный язык цифр или эмодзи. Эти повторы не следует использовать для оценки уверенности на реальной аудитории.

Каждая пятая семья целиком отложена в `holdout`; остальные — `development`. Переводы и искажённые варианты одной семьи никогда не разделяются между этими частями. Настройку выполняют по development, holdout используют один раз для итоговой оценки. После просмотра его ошибок набор уже не является новым независимым тестом для следующих исправлений.

## Запуск

```sh
node scripts/assistance-evaluate.mjs --mode baseline --split all --stage 00-baseline
node scripts/assistance-evaluate.mjs --mode current --split development --stage 01-development
node scripts/assistance-evaluate.mjs --mode current --split all --final-holdout --stage 99-final
```

Baseline — существующая категоризация без срочности и готовых ответов. Его нужно сохранять **до изменения базовой категоризации**. Current вызывает итоговую `processSupportMessage`, поэтому ошибочная маршрутизация не скрывается отдельной проверкой FAQ или срочности с заранее известной правильной категорией.

По умолчанию отчёты сохраняются вне репозитория: `../artifacts/assistance-20261031`. Можно задать `--out ПУТЬ`. Для каждой стадии сохраняются сводка, все результаты и ошибки. Для поэтапной настройки запускается 800 строк на каждый механизм; итоговый полный прогон содержит по 1000, включая отложенные семьи.

## Как читать результат

- `accuracyPercent`: совпадение маршрута и результата соответствующего механизма одновременно.
- `routeAccuracyPercent`: совпадение исходной категории.
- `componentAccuracyGivenCorrectRoutePercent`: результат нового механизма только среди случаев с правильной категорией.
- `urgency.nowRecallPercent`: сколько действительно срочных случаев попало в срочную помощь; пропуски из-за ошибочной категории тоже считаются.
- `urgency.falseNow`: сколько несрочных сообщений ошибочно подняты до «Сейчас».
- `faq.answerPrecisionPercent`: доля правильных ответов среди реально выданных. Если ответов нет, значение `null`, а не 100%.
- `faq.answerRecallPercent`: доля вопросов из проверенной базы, которые получили правильный ответ.
- `faq.unsafeAnswers`: выдан ответ не на тот вопрос либо вместо необходимой помощи.
- `faq.coveragePercent`: доля всех FAQ-проверок, на которые система ответила. В них намеренно есть отрицательные примеры и обращения других типов.

Также доступны разбивки по языкам, семействам и искажениям. Высокая общая точность может скрывать отказ отвечать на всё, поэтому точность ответов и их охват нужно рассматривать вместе. Результат не является доказательством аналогичной точности на живых обращениях.

В подробных ошибках `route_mismatch` отделён от ошибок механизма. `faq_coverage_miss` означает осторожную передачу отвечаемого вопроса человеку; это потеря охвата, а не ошибочно выданный ответ. `faq_unsafe_answer` означает выдачу неверного ответа. Если маршрут неверен, зависимое решение помечено `component_result_affected_by_route`.

## Политика меток

Срочность: `now` — продолжающееся событие, при котором нужно немедленно помочь или наблюдать; `high` — сохраняющаяся блокировка доступа, игры или значительная потеря; `normal` — завершённая ситуация без продолжающегося ущерба либо просьба без подробностей, требующая уточнения. Для сообщений не из помощи ожидается отсутствие оценки срочности.

FAQ отвечает только на значение опубликованных терминов: `faq-dm`, `faq-db`, `faq-rp`, `faq-nonrp`, `faq-ic`, `faq-ooc`, `faq-mg`, `faq-pg`, `faq-sk`, `faq-rk`, `faq-tk`, `faq-massdm`, `faq-zz`. Вопрос о разрешении, наказании, личном случае, составной или неизвестный вопрос направляется администратору. Наличие слова ДМ само по себе не разрешает выдавать справку.
