## Что изменено

- Конкурсный RAG на `gpt-6-luna`: один запрос по тексту игрока и максимум четырём исходным фрагментам правил, 14 категорий, p0–p3, шесть языков. Версия `contest-rag-3`.
- Исправлены распознавание утраты доступа, платежей и массовых сбоев, отрицания, приоритет вопросов о правилах, поиск определений и дедупликация казахского текста.
- Ответ проверяется по JSON-схеме, существующим ID источников и ограничениям черновика. Администратор проверяет применимость источников и отправляет ответ вручную. Содержание изображений не анализируется.
- Общий кэш обращений, постоянный лимит 100 попыток, ограничение частоты, четырёхсекундный deadline, ограничение размера входа и ответа API. Учитывается стоимость обычного ввода, чтения и записи кэша; перед запросом проверяется верхняя оценка $0.002.
- Исправлены конкурентная дедупликация, устаревшие уточнения после решения ИИ, состояние формы разметки и отображение режима обработки.
- Обновлены зависимости; health проверяет необходимые таблицы и показывает сведения о сборке.

## Что получилось с обучением

Fine-tuning весов GPT-6 Luna не запускался: эта модель его не поддерживает ([карточка модели](https://developers.openai.com/api/docs/models/gpt-6-luna)). Улучшение рабочих ответов достигнуто инструкциями, поиском по корпусу и проверкой результата.

Отдельный локальный TF-IDF/logistic-regression кандидат действительно обучен: 54 обучающих и 18 валидационных синтетических примеров; Python/TypeScript parity 10/10. На прежних 24 проверочных примерах raw accuracy выросла с 7/24 до 11/24, но порог уверенности не принял ни одного решения. Критерий активации не пройден, кандидат не подключён к сайту. Он не генерирует черновики и не заменяет API-модель.

Инженерная оценка демонстрационного проекта: **83/100** (алгоритмы 23/30, интерфейс 17/20, тесты 18/20, безопасность 13/15, развёртывание 12/15), ранее 70/100. Это экспертная оценка зрелости, не результат жюри. До 100 остаются проверка на реальных данных, 100 слепых оценок администраторов, KK/UZ носителями, смысловая проверка цитат и нагрузочная проверка установленной версии. `make predict` по-прежнему работает локально и не использует API RAG; его качество нужно измерять отдельно.

## Установка на ноутбуке тиммейта

1. Остановить прежний сервер штатным `stop-site.cmd`. Сохранить резервную копию `.wrangler/state`, `.sites-runtime` и локальных изменений исходников. Секрет шифрования нужен для чтения сохранённого API-ключа.
2. Установить проверенные исходники. Архив поставки содержит код без `.git`, базы, API-ключа и приватного корпуса. Не заменять существующие локальные файлы с секретами или базой файлами из другого компьютера. Если есть собственные изменения кода, сначала сравнить их с обновлением.
3. Из папки проекта выполнить:

```powershell
npm run install:ci
npm run triage:prepare -- --rules ПУТЬ_К_rules.json
npm run release:check
```

4. Для существующей базы выполнить только недостающие миграции. Если 0000–0007 уже применены:

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0008_ai_rate_limits.sql
```

Если 0007 ещё нет, сначала применить `drizzle/0007_triage_history.sql` той же командой. Для новой пустой базы порядок всех девяти миграций указан в README. Старые миграции не запускать повторно вслепую.

5. Запустить `npm start -- --port 8787`. На `http://127.0.0.1:8787/api/health` проверить `ok: true` и новое время `build.builtAt`. Из архива без Git `build.commit` честно равен null; в Git-копии виден коммит и признак dirty.
6. На локальной странице `/settings` выбрать `gpt-6-luna`, сохранить имеющийся ключ и включить ИИ. Ключ не передавать через публичную ссылку. Настройки и ключ из тестовой базы в архив не включены.
7. Для публичной ссылки остановить `npm start` и запустить `start-site.cmd`. Новый адрес туннеля может отличаться от прежнего. Проверить одну синтетическую заявку, черновик, источники и ручную отправку именно на этом сервере.

Рабочая публичная версия будет считаться обновлённой только после этих действий. Данные временной проверки на компьютере автора не являются базой сервера тиммейта.
