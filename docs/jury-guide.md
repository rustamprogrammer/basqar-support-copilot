# Руководство для жюри и команды

Basqar запускается на компьютере проверяющего. Публичная ссылка и постоянно работающий сервер команды не требуются. Описание продукта и измеренные результаты — в [README](../README.md); здесь приведены установка, сценарий проверки и эксплуатационные команды.

## Локальный запуск

### Требования

- **Node.js 24.x** с npm. После установки откройте новый терминал.
- Git и доступ к репозиторию.
- Приватный **`rules.json`** из конкурсной выдачи. Получите его у организаторов или уполномоченного участника команды; файл не публикуется в Git.
- Для режима ИИ — отдельно переданный ключ команды или собственный разрешённый OpenAI API-ключ. Без него доступны локальные алгоритмы, интерфейс и тесты.

Первичная установка зависимостей требует сети. Локальные алгоритмы после подготовки не вызывают API. Отдельный сервер базы и аккаунт Cloudflare для локального запуска не нужны.

### 1. Скачать и подготовить

Команды выполняются в PowerShell. Замените пример пути на расположение вашего `rules.json`.

```powershell
git clone https://github.com/BAITC-Hacks/hack-b6eba4f7-basqar.git
cd hack-b6eba4f7-basqar
npm run setup:local -- --rules "C:/private/handout/rules.json"
```

Команда устанавливает зависимости, готовит `lib/triage/corpus.local.json`, собирает сайт и проверяет схему локальной БД. Для пустой базы выполняются все девять миграций; уже готовая база сохраняется. Если обнаружена частично обновлённая база, команда остановится: см. [обновление существующей базы](#upgrading-existing-database). С флагом `--skip-install` можно пропустить установку при уже проверенных зависимостях.

Если конкурсная выдача находится в архиве, используйте вместо `--rules` команду `npm run setup:local -- --archive "C:/private/handout.tgz"`. Для извлечения нужен `tar`; укажите ровно один источник: `--rules` или `--archive`.

Корпус исключён из Git и нужен на каждой новой машине. Из конкурсной выдачи используются правила; реальные обращения для сборки не требуются. Подготовка не копирует API-ключ и не включает ИИ.

Публичный GitHub CI создаёт минимальный **синтетический** корпус для проверки кода и сборки без приватной выдачи. Это не настоящие правила и не замена корпуса для демонстрации или измерения качества.

### 2. Запустить

```powershell
npm start -- --port 8787
```

Откройте [http://127.0.0.1:8787](http://127.0.0.1:8787) и [проверку состояния](http://127.0.0.1:8787/api/health). Оставьте процесс работать. Чистая установка запускается с `processingMode: "rules"`, `aiReviewEnabled: false`, `publicDemo: true`. Остановка — **Ctrl+C**. База в `.wrangler/state/` сохраняется между запусками; повторно устанавливать зависимости и создавать базу каждый раз не нужно.

### 3. При необходимости включить ИИ

Во втором терминале из корня проекта выполните `npm run ai:configure` после подготовки `.dev.vars`, описанной ниже. Клон из GitHub не содержит ключ и не включает платные вызовы автоматически. Локальная установка не может воспроизвести режим ИИ без отдельно предоставленного действующего ключа.

## Ключ команды и расходы

1. Создайте локальный файл по шаблону, **не перезаписывая существующий**:

   ```powershell
   if (-not (Test-Path -LiteralPath .dev.vars)) { Copy-Item -LiteralPath .dev.vars.example -Destination .dev.vars }
   notepad .dev.vars
   ```

2. Вставьте отдельно полученный ключ в поле `OPENAI_API_KEY` и сохраните файл. Не вставляйте секрет в командную строку, README, issue или снимок экрана. `.dev.vars` игнорируется Git; [.dev.vars.example](../.dev.vars.example) содержит только шаблон.
3. При работающем сервере во втором терминале:

   ```powershell
   npm run ai:configure
   ```

   По умолчанию используются файл `.dev.vars` и порт `8787`. Явные параметры: `npm run ai:configure -- --key-file .dev.vars --port 8787`.
4. Откройте локальные [настройки](http://127.0.0.1:8787/settings) и `/api/health`: должны быть включённый ИИ и режим `rules+ai`. Первая содержательная заявка при включённом ИИ уже может быть платной.

Команда сначала проверяет готовность сервера, затем через loopback `/api/settings` сохраняет ключ, модель `gpt-6-luna` и режим `uncertain`. **Платного проверочного вызова нет**, общий счётчик попыток не сбрасывается. Если ключ уже настроен, он сохраняется без чтения файла; намеренная замена — `npm run ai:configure -- --replace-key`. При исчерпанном лимите команда откажет, вместо скрытого сброса счётчика.

Вместо команды ключ можно ввести вручную в локальных настройках, выбрать `gpt-6-luna`, включить ИИ и сохранить. Пустое поле оставляет сохранённый ключ; «Удалить ключ» отключает ИИ. Необязательная кнопка «Проверить · 1 платный запрос» расходует отдельную попытку и проверяет прежний путь пяти маршрутов, а не весь конкурсный сценарий. Настройка ключа через публичный туннель запрещена.

Ключ зашифрован в локальной БД, интерфейс показывает только последние четыре символа. `.dev.vars` содержит исходный секрет и также должен оставаться приватным. Секрет шифрования `.sites-runtime/settings-secret` сохраняйте вместе с резервной копией `.wrangler/state/`. Эти файлы, локальные логи и приватный корпус не включаются в Git или публичные артефакты.

Ограничения рабочего сервера:

- Общий постоянный лимит **100 попыток**, включая ручные проверки, ошибки и тайм-ауты. Замена ключа, выключение ИИ и перезапуск его не сбрасывают.
- До 6 новых проверок в минуту на сессию браузера и 20 на установку; совпадающие входы и источники могут использовать кэш без повторной оплаты. Смена `ticket_id` сама по себе не заставляет повторно оплатить тот же запрос.
- Один запрос модели, без автоматического платного повтора; deadline до 4 секунд. Перед отправкой проверяется верхняя оценка стоимости **$0.002** по настроенному тарифу. Это не общий долларовый лимит аккаунта.
- Режим `uncertain` пропускает лишь ограниченный проверенный русский FAQ без условий и короткие приветствия; `all` проверяет также их. На сложном наборе режим всё равно сделал 99 вызовов на 100 обращений.
- Неподдерживаемая модель, исчерпанный лимит, ошибка API или непринятый ответ оставляют локальный результат для человека. Валидный JSON также может содержать смысловую ошибку.

По зафиксированным прогонам: финальные 100 — $0.024653325 известных токенных затрат, новые 20 — $0.005098625. Итог зависит от токенов, модели, тарифа и биллинга провайдера. Полный журнал, включая промежуточные и неуспешные попытки, описан в [отчёте](adversarial-verification-2026-10-31.md). Исследовательские CLI-прогоны имеют отдельный бюджет и обходят рабочий счётчик приложения; не запускайте их как часть обычной демонстрации.

## Сценарий проверки

| Действие | Где смотреть | Что проверить |
| --- | --- | --- |
| Отправить `Что такое ДМ?` | «Проверка сообщения», `/` | Опубликованная справка, источник и возможность попросить администратора. |
| Отправить сообщение об утрате доступа к аккаунту | `/`, затем «Обращения», `/?view=inbox` | Конкурсная категория, p0, очередь «Сейчас», черновик без автоматической отправки. Это проверяемый сценарий, не гарантия безошибочного результата. |
| Отправить своё вымышленное обращение на KK / UZ / EN / ES / PT | «Проверка сообщения» | Определение языка и язык черновика; смысл следует проверить вручную. |
| Открыть обработанное обращение | «Логика обработки», `/logic` | Локальный маршрут, участие ИИ, причины, исходные фрагменты правил. |
| Исправить текст и отправить ответ | «Обращения» | Черновик редактируется, отправку выполняет человек. |
| Проверить несколько текстов без API | «Тесты и статистика», `/quality` | До 1000 строк, порции по 10; запуск можно остановить. Используются локальный алгоритм и начальные FAQ, обращения не сохраняются. |

Используйте только синтетические обращения. В открытом деморежиме посетители этой установки видят общую очередь, могут отвечать и менять базу знаний. Массовое удаление через «Управление тестовыми данными» затрагивает общую базу и требует подтверждения.

Маршруты «Вопрос / Помощь / Нарушение / Корзина / Не определено», конкурсные 14 категорий и приоритеты p0–p3 — разные поля. В очереди отдельно показывается срочность «Сейчас / Высокий / Обычный». Принятый результат ИИ с p0 повышает её до «Сейчас», с p1 — минимум до «Высокий». Само слово «срочно» не доказывает происшествие. Срочный запрос не должен ждать заполнения всех деталей.

Разметка, обратная связь «Помогло / Нужен администратор» и изменение карточек не обучают веса модели автоматически. В `/knowledge` опубликованные карточки отделены от черновиков. Личный инцидент, условия и несколько тем не должны заменяться словарной справкой. Сгенерированный ИИ текст всегда остаётся черновиком для администратора.

## Проверка состояния и API

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health
```

Поля ответа:

- `ok: true` — необходимые таблицы доступны; отсутствие миграций даёт HTTP 503.
- `processingMode: "rules"` / `"rules+ai"`, `aiReviewEnabled`, `aiMode` — конфигурация. Включённый ИИ может пропустить FAQ, упереться в лимит или вернуть ошибку; фактический режим есть у отдельного результата.
- `aiUsed`, `aiLimit` — общий расход попыток, максимум 100.
- `publicDemo`, `adminConfigured` — режим доступа.
- `build.commit`, `build.dirty`, `build.builtAt` — происхождение сборки. В архиве без Git коммит равен `null`; обновление исходников без пересборки не обновляет сервер.

**`POST /triage`** принимает JSON заявки. Пример отправляет один запрос и может использовать оплачиваемый API, если ИИ включён:

```powershell
$ticket = @{
  ticket_id = 'jury-example-1'
  kind = 'complaint'
  images_count = 1
  reported_nick = 'Sample_Player'
  messages = @(@{
    role = 'player'
    text = 'Игрок Sample_Player оскорбил меня в чате. Прикладываю снимок.'
  })
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8787/triage `
  -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($ticket))
```

Основные поля ответа: `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted`, `draft_reply`, `needs_human`, `confidence`, `reasons`, `meta`. В `draft_reply` находятся текст и ссылки на правила; `meta` содержит режим, версию корпуса, источники, время и сведения о стоимости. `confidence` — эвристика, а не измеренная вероятность правильного ответа. Изображения не анализируются: учитывается лишь наличие вложений.

Запрос `/triage` не создаёт карточку веб-очереди: сохранение обращения идёт через **`POST /api/messages`** из интерфейса. Точный контракт, лимиты входа, категории и дедупликация описаны в [triage.md](triage.md).

Пакетный режим без API и ключа:

```powershell
npm run triage:predict -- --in tickets.jsonl --out pred.jsonl
```

При установленном Make доступна эквивалентная команда `make predict IN=tickets.jsonl OUT=pred.jsonl`. Она проверяет локальный алгоритм; её результат нельзя выдавать за результат связки с API-моделью.

## Обновление существующей базы и инженерная проверка

Остановите сервер. Сохраните локальные изменения, резервные копии `.wrangler/state/` и `.sites-runtime/`; секреты и приватные файлы другой установкой не заменяйте. Затем:

```powershell
git pull --ff-only
npm run setup:local -- --rules "C:/private/handout/rules.json"
npm run release:check
npm start -- --port 8787
```

Если `setup:local` остановился на старой или частичной схеме, не продолжайте запуск и не удаляйте базу. Уточните, какие миграции уже применены, и выполните только недостающие команды из [ручного пути](#ручной-путь-подготовки-базы). Например, после уже применённых 0000–0007 нужна только `0008_ai_rate_limits.sql`; если нет 0007, сначала примените её. Затем повторите подготовку и проверку. Автоматический setup намеренно не угадывает историю частичной базы.

Сверьте `build.builtAt` и доступные сведения о коммите в `/api/health`. Перезагрузка ноутбука без установки кода и сборки не обновляет проект.

`release:check` включает тесты, TypeScript, ESLint и production-сборку без платных API. Можно запускать отдельно:

```powershell
npm test
npm run typecheck
npm run lint
npm run build
```

Для разработки: `npm run dev -- --hostname 127.0.0.1`, адрес `http://127.0.0.1:5173`. Демонстрационный режим и итоговые HTTP-проверки выполняйте через production-сборку и `npm start`.

Сохранённая статистика прошлых версий и авторские регрессии не являются свежей оценкой качества. На изученных 100 сложных примерах связка дала 97/100 полностью правильных решений, на новых 20 — 17/20 и распознала 4/6 критических случаев. Оба набора маленькие и синтетические, без независимой проверки носителями; методика, расходы и оставшиеся ошибки — в [отчёте](adversarial-verification-2026-10-31.md).

## Ручной путь подготовки базы

Этот раздел сохраняет команды для диагностики и ручного обновления. При успешном `setup:local` повторять миграции вручную не нужно. **Не запускайте все старые миграции на существующей базе.**

Зависимости и сборка отдельно:

```powershell
npm run install:ci
npm run triage:prepare -- --rules "C:/private/handout/rules.json"
npm run build
```

При исходном архиве вместо `--rules` можно использовать `npm run triage:prepare -- --archive "C:/private/handout.tgz"` (нужен `tar`). Для совершенно **пустой базы** девять миграций выполняются в этом порядке, один раз:

```powershell

node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_sloppy_joshua_kane.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_greedy_charles_xavier.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_feedback.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0004_feedback_routing.sql
```

## Режим доступа

`npm start` по умолчанию включает открытый демонстрационный режим. Посетители этой установки имеют доступ к общей очереди, ответам, разметке и базе знаний; API-ключ и ручная платная проверка доступны только через локальный адрес.

Для закрытого режима задайте переменную перед запуском:

```powershell
$env:SUPPORT_DEMO_MODE='false'
npm start -- --port 8787
```

Тогда пароль хранится в `.sites-runtime/admin-password.txt`, а обычный посетитель видит обращения своего браузера. Для возврата деморежима удалите переменную или установите `SUPPORT_DEMO_MODE=true` и перезапустите. Старый файл пароля сам по себе не закрывает открытый демостенд.

## Необязательно: публичная ссылка с ноутбука

Локальная проверка жюри не требует туннеля. Если команде нужна удалённая демонстрация, установите `cloudflared` и проверьте `cloudflared --version`.

1. После сборки, миграций и настройки ключа остановите foreground-сервер через Ctrl+C.
2. Запустите `./start-site.cmd` из PowerShell или двойным щелчком.
3. Возьмите адрес из окна запуска или `site-link.txt`; `open-site.url` повторно открывает сайт. Проверьте `/api/health` именно по этому адресу.

Сервер и туннель работают в фоне. Ноутбук должен оставаться включённым, подключённым к интернету и без спящего режима. После нового туннеля адрес может измениться; повторное открытие скрипта при работающем сервере показывает уже имеющуюся ссылку. Остановка — `stop-site.cmd`, база сохраняется. Если туннель не поднялся, локальный сайт может продолжать работать; прочитайте сообщение запуска.

В macOS/Linux запустите сайт обычной командой и в другом терминале:

```sh
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8787 --protocol http2
```

Оба процесса должны оставаться запущенными. В публичном деморежиме очередь доступна всем посетителям ссылки, поэтому не используйте реальные персональные обращения.

## Если запуск не удался

| Симптом | Действие |
| --- | --- |
| `node` / `npm` не найдены | Установить Node.js 24.x и открыть новый терминал. |
| Нет приватного корпуса | Получить конкурсный `rules.json`, затем повторить подготовку с его путём. |
| Нет `dist/server/wrangler.json` | Выполнить сборку перед ручными миграциями и запуском. |
| `no such table`, `no such column`, health 503 | Проверить недостающие миграции 0000–0008; не повторять все на существующей базе. |
| `ai:configure` не видит сервер | Сначала запустить `npm start`, сверить порт и `/api/health`. |
| Включён ИИ, но обращение обработано локально | Проверить результат, счётчик, режим и причину отказа; FAQ может пропускать API. |
| Требуется неожиданный пароль | Проверить `SUPPORT_DEMO_MODE`, использовать штатный запуск и перезапустить процесс. |
| На сайте прежняя версия | Установить исходники, собрать и перезапустить именно обслуживающий запросы сервер. |
| Нет необязательной публичной ссылки | Проверить cloudflared, интернет и сообщение запуска; локальный сервер проверять отдельно. |

Основные модули: `lib/support-processing.ts` и `lib/help-urgency.ts` — локальная обработка; `lib/knowledge-base.ts` и `lib/knowledge-matching.ts` — FAQ; `lib/triage/` — контракт, RAG и лимиты; `app/api/messages/` — сохранение; `db/` и `drizzle/` — база; `scripts/start-local.mjs` и `scripts/local-public.ps1` — сервер и необязательный туннель.
