# Обработка обращений и проверка качества

Проект команды Basqar для хакатона: сайт для отправки и проверки обращений. Система исправляет известные опечатки и слитные сочетания игрового жаргона, различает вопрос и просьбу о помощи, направляет обращение администратору. Короткие сообщения без содержания попадают в корзину. Неясные обращения остаются на проверке с пометкой «Нужно уточнение». Администратор принимает или отклоняет обращения.

Новые обращения проходят гибридную обработку: **алгоритм → проверка ИИ → итог**. Сначала существующие правила предлагают исправленный текст, категорию и уточняющий вопрос. ИИ получает исходное сообщение и компактный результат алгоритма, проверяет их и либо подтверждает результат, либо сразу возвращает собственный полный вариант. Смысл определяется по исходнику; предложение алгоритма может быть ошибочным. ИИ не меняет код или правила, не обучает алгоритм и не объединяет два конкурирующих решения. Ответ игроку и наказание автоматически не назначаются.

Раздел **«Логика»** показывает сохранённые этапы конкретного обращения. В базе остаются исходник, первоначальный результат алгоритма, исход проверки ИИ и окончательный результат. Для уточнения передаются исходное обращение с дополнением, предыдущая категория и заданный вопрос. Если ИИ отключён, недоступен или достигнут лимит, сохраняется результат алгоритма с явной отметкой, что он не проверен ИИ. Исторические записи не пересчитываются. Повторная отправка с уже сохранённым ID возвращает сохранённый результат.

Примеры ниже описывают исходный результат правил; ИИ может его исправить.

| Сообщение | Результат |
| --- | --- |
| `123` | В корзину |
| `помощь` | Администратору на проверку |
| `памагите` | Исправляется на `Помогите`, затем на проверку |
| `pomogite`, `gjvjubnt`, `пoмoгитe` | Известный транслит, раскладка или смешанные буквы → `Помогите` |
| `komektesiniz` | Восстанавливается `Көмектесіңіз`; словарный смысл — «помогите» |
| `неработает кнопка` | Исправляется на `Не работает кнопка`, затем на проверку |
| `У мня не удеться зойти` | Исправляется на `У меня не получается зайти`, затем на проверку |
| `Помощь больше не нужна` | В корзину |
| `оскродни` | `Оск родни` → Помощь |
| `дмвзз` | `ДМ в ЗЗ` → Помощь |
| `менядмятвзз` | `Меня ДМят в ЗЗ` → Помощь |
| `Что значит ДМ?` | Вопрос по игре → администратору |
| `дали варн хотя я защищался` | Помощь → администратору |
| `ПП на КВ` | Сохранение текста → нужно уточнение |
| `meni sababsiz o'ldirdi` | Словарный разбор: `меня без причины убил` → Помощь |
| `мені ұрып жатыр возле ЗЗ` | Разбор казахских слов и ЗЗ → Помощь |
| `men onadan so'kmadim` | Отрицание сохраняется: `я не оскорблял родню` → нужно уточнение |
| `меня взяли под стражу без объяснения` | Помощь |
| `/warn 123` | Команда сохраняется без изменения |
| `Ты дурак` | В раздел «Нарушения» |
| `Меня оскорбили: «ты дурак»` | Помощь → администратору |
| `этот пидорас заебал меня, damn it, помогите админы` | Помощь → администратору для уточнения |
| `Админ, ты идиот, помоги` | В раздел «Нарушения» |
| `Ты идиот, это шутка` | В раздел «Нарушения» |

Рядом с «Корзиной» есть раздел **«Нарушения»**. После восстановления известных вариантов раскладки/транслита правила проверяют прямое оскорбление автора. При срабатывании локальный этап завершается: дальнейшее исправление, перевод и определение темы внутри алгоритма не запускаются. В новых обращениях этот результат тоже проходит проверку ИИ, который может подтвердить или заменить его. Если проверка не состоялась, категория правил сохраняется с соответствующей отметкой. Прежние записи, обработанные только правилами, остаются в своей исторической версии.

В карточке и «Логике» сохраняется причина. Администратор при необходимости может вручную переместить обращение в «Нарушения» или вернуть его на проверку; обязательного решения для этого раздела нет. Цитаты, пересказ чужой речи и отрицания исключаются из автоматической отметки в известных правилам случаях. Это ограниченный набор правил, а не определение всех нарушений: сложный контекст и замаскированные оскорбления могут быть пропущены. Автоматического наказания нет.

Проверка учитывает, к кому относится ругань: сама комбинация мата и слова «админ» не означает нарушение. Описание действий другого человека остаётся возможной жалобой; без конкретного события требуется уточнение. Прямое оскорбление собеседника сохраняет приоритет, даже если в том же сообщении есть жалоба или просьба о помощи. Оправдание собственного оскорбления словами «шутка», «шучу», «рофл», «пранк» не отменяет нарушение. Упоминание шутки без оскорбления и пересказ чужой шутки сами по себе не считаются нарушением. Причина отображается на этапе «Проверка нарушения».

Первоначальное исправление работает локально по словарю и правилам, без нейросети и API-ключей. Сокращения остаются игровыми: `dm` → `ДМ`, `дмят` → `ДМят`, без замены на длинные объяснения. Разделяются только знакомые сочетания, неизвестные слова сохраняются. Короткие коды не сравниваются по похожести: `ДМ` и `ДБ` не заменяют друг друга. Фрагменты в двойных и типографских кавычках, код, ссылки, никнеймы с подчёркиванием и идентификаторы защищены от исправлений. Исходное сообщение сохраняется вместе с исправленным. Одинарные кавычки и простой ник без @, подчёркивания или кавычек могут не распознаться как защищённый фрагмент; исправленная версия требует проверки в таких случаях. Подключённый ИИ отдельно проверяет весь результат и при необходимости заменяет его, сохраняя смысл исходника.

Правила учитывают цель: жалоба на игрока, обжалование наказания, действия администрации, вопрос по игре, помощь, аккаунт/имущество или платёж. `130дм` преобразуется в `130 ДМ`, но `Alex_130дм`, `dm130`, ссылки и цитаты сохраняются. «Покажи фрапс на мой ДМ» распознаётся как обжалование; «Какой пункт указать за ДБ?» — как вопрос. Узбекское `db` в известном языковом окружении не подменяется обвинением в ДБ. Неизвестные ошибки и сложные случаи могут остаться нераспознанными.

### Правила и контроль качества

Локальный этап rules-5 работает на словарях и правилах: без LLM, обучаемого классификатора и внешних API. Знакомые варианты раскладки и транслита восстанавливаются до проверки собственного нарушения автора, затем исправляется текст и разбирается смысл. Маршрут выбирается по цели: справочный ответ или действие администратора. Уточнение независимо от категории. Это ограниченный разбор по шаблонам, не универсальное понимание языка. В обработке новых сообщений за ним следует отдельная проверка ИИ, если она включена на сервере.

В rules-5 добавлена проверка цели на самом русском, казахском, украинском и узбекском тексте: вопрос о способе действия, просьба проверить ситуацию, описание пропажи или неисправности. Полный перевод не требуется. Иностранные оскорбления проверяются с учётом адресата, отрицаний и пересказа чужой речи. Восстановление опечаток ограничено словарём; корректные слова, игровые сокращения, цитаты и идентификаторы защищены.

Раздел «Качество» содержит историю прогонов на 10 000 синтетических сообщениях, отдельную новую выборку из 400 сообщений, PDF-отчёт и полный реестр ошибок. Разметка подготовлена до проверки алгоритма и отдельно проверена другим агентом, но не подтверждена администратором игры. Повторные прогоны по знакомым примерам показывают результат доработок, а не независимую точность на реальных обращениях. Это исторические показатели правил, а не оценка нового гибридного режима. Для повторной проверки правил без добавления дублей доступен POST `/api/quality/evaluate` с JSON `{"texts":["Что такое ДМ?"]}`. Он не обращается к платному API и не записывает сообщения в базу. Точность, задержка и стоимость гибридного режима требуют отдельного измерения; экономия пока не установлена.

Транслит (`pomogite`), неверная раскладка (`gjvjubnt`) и смешанные похожие буквы (`пoмoгитe`) проверяются отдельно. Преобразуются только знакомые слова и сочетания русского/казахского языка, а не весь латинский текст подряд. Распознанные изменения видны в шаге «Раскладка и транслит», исходник сохранён. Неизвестные варианты, защищённые цитаты, ссылки и ники остаются без изменения. Полное восстановление любой казахской раскладки, замена цифр на казахские буквы и универсальное распознавание оскорблений в транслите не реализованы.

«Качество» показывает каждый этап на одной фиксированной тысяче, дополнительную регрессию на 1300 знакомых сообщениях и отдельную новую тысячу. Перед первым прогоном примеры новой тысячи и близкие повторы прежних наборов исключены из настройки. Последующий разбор ошибок и повторный прогон этой тысячи показаны отдельно и уже не считаются независимой проверкой. Разметка предварительная, подготовлена ассистентами; подтверждённых человеком меток в этом прогоне нет. Неопределённая категория и спорная разметка учитываются отдельно от ошибок. Качество исправленного текста проверяется отдельными контрастными тестами. Для этих исторических наборов публикуются агрегаты; реальные обращения и выгрузки базы остаются вне Git. Отдельный синтетический набор на 10 000 сообщений доступен в архиве раздела «Качество».

В панели администратора есть **«Указать правильный результат»**. Категория, исправление и заметка сохраняются как предложение. Роли в демо открыты всем, поэтому нажатие кнопки не меняет правила и не превращает предложение в проверенный эталон. Скачайте предложения через «Качество», проверьте содержание и явно выберите ID для контрольных примеров:

```powershell
npm run rules:review -- --input feedback.jsonl --output reviewed.jsonl --approve-ids id1,id2 --fixtures-output evaluation.jsonl
npm run routing:evaluate -- --input evaluation.jsonl --output .sites-runtime/routing-report.json
```

Для отклонения используйте --reject-ids вместо --approve-ids, без --fixtures-output. Команда не перезаписывает файлы, не допускает неизвестные ID или конфликтующие метки. Только выбранные при этом запуске записи экспортируются как human-reviewed; импортированный статус approved сам по себе недостаточен. Правила исправляются отдельно, после проверки новых примеров и всей регрессии.

Формат evaluation.jsonl: id, text, expectedRoute (`question`, `help`, `violation`, `trash` или `null`), needsClarification (`true`, `false` или `null`), labelStatus. Для сравнения добавьте `--baseline before.json` со старым отчётом по тому же файлу разметки. Сравнение не разрешает незаметную смену текстов или меток.

Публикация проверенных агрегатов: создайте `.sites-runtime/stage-index.json`, перечислив отчёты относительно этого каталога. Для одного отчёта из команды выше:

```json
{"stages":[{"file":"routing-report.json","title":"Проверка"}]}
```

```powershell
npm run routing:publish -- .sites-runtime
npm test
npx tsc --noEmit
```

После проверки соберите и перезапустите сайт. Исторические scripts/ml и lib/intent-model.ts оставлены для воспроизводимости прежней версии, но обработчик их не импортирует. Не помещайте реальные обращения или выгрузки в Git; используйте игнорируемую data/ или каталог вне проекта. Для следующего независимого измерения потребуется новый отложенный набор.

Смешанный текст разбирается по известным узбекским, казахским и украинским словам и сочетаниям. Словари охватывают жалобы, вход в игру, оплату, транспорт, семью, чат и интерфейс. Поддерживаются известные опечатки, варианты апострофов, слитное написание знакомых фраз и смешанные похожие буквы. Для узбекских словарных вариантов распознаётся также кириллица; для знакомых украинских просьб — транслит и английская раскладка.

Фразы проверяются раньше отдельных слов, отрицательные формы записаны отдельно. Неоднозначные слова выбираются по соседним признакам языка в том же предложении: например, казахское «мені» означает «меня», украинское — «мне». При равных основаниях исходное слово сохраняется. Это частичный словарный разбор для классификации, а не полноценный машинный перевод: неизвестные слова остаются на месте, порядок слов может быть неграмматичным. Внутри локального алгоритма исходное сообщение и его исправленная версия не заменяются словарным переводом; разбор виден в «Логике». Подключённый ИИ может вернуть полный русский вариант текста с сохранением смысла, жаргона, имён, чисел, цитат и других значимых деталей. Язык сообщения не определяет национальность автора или наличие нарушения на национальной почве. Автоответы не включаются.

Расшифровка жаргона используется для понимания: например, ЗЗ — зелёная зона. В основном тексте сохраняются короткие формы ДМ, ДБ, ЗЗ и другие знакомые администраторам обозначения. Жалоба на связывание в ЗЗ направляется на проверку; программа не назначает наказание и не утверждает доказанность нарушения.

### Уточнения

Если деталей не хватает, пользователю и администратору показывается конкретный вопрос: например, что означает ПП или какое наказание получено. Пользователь может нажать «Дополнить». Ответ вместе с исходным текстом обрабатывается заново и сохраняется отдельной записью со ссылкой на оригинал. Общий лимит — 2000 символов; повтор сетевого запроса с тем же ID не создаёт дубль. Старое обращение и его история сохраняются. Отправка ответа администратором в чат и обучение будущей модели пока не реализованы.

## Сортировка по цели обращения (purpose-v1)

Основные категории — «Вопрос», «Помощь», «Нарушение»; очевидно посторонние сообщения идут в корзину. Неопределённая категория остаётся у администратора. Отсутствие ID или другой детали не отменяет уже распознанную помощь. Состояние обработки и просьба уточнить хранятся отдельно от категории.

Категорию сначала предлагают локальные правила и словари, затем подключённый ИИ подтверждает или заменяет весь результат обработки. Исторический обученный классификатор не вызывается. Автоответы не включены; категория «Вопрос» сама по себе не означает готовность к автоответу. Исправления администратора сохраняются как предложения, не изменяют правила и не запускают обучение. Команды оценки ниже проверяют только локальный алгоритм.

Проверка новой схемы на одном неизменном наборе:

```sh
npm run routing:evaluate -- --input labels.json --output before.json --lib path/to/old/lib --stage before
npm run routing:evaluate -- --input labels.json --output after.json --baseline before.json --stage after
```

В `labels.json` нужен массив записей `{id, text, expectedRoute, needsClarification, labelStatus}`; принимается и JSONL. `expectedRoute`: `question`, `help`, `violation`, `trash` или `null`; `needsClarification`: `true`, `false` или `null`. Метка `assistant-provisional` не считается подтверждённой человеком. При сравнении файл разметки должен совпадать побайтно, отчёты не перезаписываются. Набор для окончательной проверки откладывается до настройки правил и оценивается отдельно.

На странице `/quality` показаны агрегаты и ссылки на отчёты и архив синтетического набора на 10 000 сообщений. Реальные обращения, выгрузки базы и новые локальные отчёты автоматически не публикуются. Правильность исправленного текста — отдельная проверка: совпадение категории не доказывает качество исправления каждой фразы.

Экспорт `/api/feedback` содержит предложения. Сначала администратор вручную проверяет выбранные примеры, затем запускает:

```sh
npm run rules:review -- --input feedback.jsonl --output reviewed.jsonl --approve-ids selected-id --fixtures-output fixtures.jsonl
npm run routing:evaluate -- --input fixtures.jsonl --output checked.json
```

Для новой оценки нужны записи `routingSchema: "purpose-v1"`; прежние узкие темы остаются историческими и требуют новой разметки. Команда проверки не подключает примеры к работающему обработчику.
